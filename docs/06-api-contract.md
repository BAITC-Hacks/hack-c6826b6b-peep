# API этапа 2

Все персональные и HR-запросы требуют `Authorization: Bearer <token>`. Токен выдаёт сервер после входа; переданная клиентом роль не используется. Срок сессии — 8 часов, выход отзывает токен. Ответы API помечены `Cache-Control: no-store`.

## Доступ

| Метод и путь | Доступ | Результат |
| --- | --- | --- |
| `POST /api/auth/login` | Без сессии | `{token, user, expires_at}` по `{username, password}` |
| `GET /api/auth/me` | Авторизованный | `{username, role, employee_id, display_name}` |
| `POST /api/auth/logout` | Авторизованный | `{logged_out: true}` |
| `GET /api/meta` | Авторизованный | `{roles: [...], skills: [...]}` — справочники для выбора цели |
| `GET /api/me/profile` | Сотрудник | Свой профиль |
| `GET /api/employees/{id}` | HR или владелец | Профиль; чужой ID сотруднику возвращает 403 до проверки существования |
| `GET /api/employees/{id}/history` | HR или владелец | `{history: [...]}` |
| `PUT /api/me/goal` | Сотрудник | Сохраняет `{target_role, target_grade}`, возвращает профиль |
| `DELETE /api/me/goal` | Сотрудник | Удаляет личный выбор и возвращает профиль с исходной целью/предложением |
| `GET /api/hr/employees?q=...` | HR | `{employees: [...], total}` — поиск по имени, ID, отделу и роли |

401 означает отсутствие/истечение/отзыв сессии. 403 означает отсутствие права. 404 — объект не найден после проверки права. 422 — ошибка формата или недоступная цель. Тело ошибки: `{detail: "сообщение"}`; стандартные ошибки FastAPI могут содержать массив ошибок в `detail`.

## Ответ профиля

```text
employee           исходные поля профиля из принятого набора
goal               личная или исходная цель; null, если цель не задана
suggested_goal     предложение следующего существующего грейда той же роли; не сохранённая цель
goal_source        personal | dataset | suggested | none
skills[]           skill_id, name, type, category, assessed_level, required_level, critical
stats              completed, total, in_progress, mandatory_pending
history[]          исходные поля записи + title, type, mandatory
calculation        {status: "not_calculated"}
```

`assessed_level` — последняя оценка, не прирост от активности. Для отображения требований используется цель, а при её отсутствии — отдельно обозначенное предложение. Для Lead следующий грейд не создаётся. Показатели истории — количества исходных записей, не игровые очки и не рейтинг сотрудников.

## Импорт

`POST /api/hr/import/preview` — multipart:

- `employees_file`: UTF-8 JSON с массивом профилей либо объектом `{employees: [...], meta?: ...}`.
- `history_file`: UTF-8 CSV; колонки ровно из исходной схемы. Пустые `due_date`, `score`, `feedback_rating` допустимы.
- `conflict_policy`: `reject` (по умолчанию) или `replace`.

Нужен хотя бы один непустой файл. Ограничения: 5 МБ на файл, 2 000 профилей и 20 000 записей истории за запрос. ID состоят из латинских букв, цифр, `_`, `-`, `.`, начинаются с буквы/цифры, длина до 100 символов. `manager_id` — корректный ID или JSON `null`; пустая строка не является отсутствующим руководителем. Уровни навыков — целые числа 0–5, boolean не принимается.

Предпросмотр возвращает:

```json
{
  "preview_id": "<opaque-id>",
  "expires_at": 0,
  "summary": {
    "employees": {"added": 1, "updated": 0, "unchanged": 0},
    "activities": {"added": 1, "updated": 0, "unchanged": 0}
  },
  "warnings": []
}
```

`expires_at` в этом примере условный: реальный ответ содержит Unix-время истечения через 15 минут. Предпросмотр хранится отдельно и не меняет рабочие записи.

`POST /api/hr/import/commit` с `{preview_id}` применяет весь пакет в одной SQLite-транзакции и возвращает HTTP 201, тот же отчёт и `committed: true`. При изменении рабочих данных после предпросмотра, истечении времени или повторном подтверждении — HTTP 409 без изменений. Превью привязано к создавшему его HR-аккаунту.

Идентичные существующие записи учитываются в `unchanged`. Отличающиеся ID при `reject` отклоняют пакет с 409. `replace` меняет текущую исходную запись, сохраняя её первую версию и личную цель отдельно. При ошибке ссылок, типов или дубле ID внутри одного файла — 422 без записи пакета. Новая история может ссылаться на новый профиль в том же пакете.

## Что отсутствует

Нет endpoints рекомендаций, подтверждения прохождения и расчётного изменения навыков. Эти операции относятся к следующим этапам. `/api/health` остаётся техническим endpoint для разработки; сводка среза убрана из веб-сценария и публичного API.
