# Проверка этапа 2

Дата: 23 сентября 2026. Среда: Linux, Python 3.14.7, Flutter 3.47.5 / Dart 3.13.4. Работа выполнена локально.

## Автоматические проверки

- `python -m pytest -q`: 50 тестов успешно. Проверены авторизация и отзыв сессии, запрет чтения чужих профилей и истории, HR-права, личная цель и её отделение от исходного профиля.
- Импорт: новый профиль и связанная история одним пакетом; идемпотентность; конфликт ID и явная замена; ошибочные ссылки; атомарный отказ; истёкший, устаревший и повторно использованный предпросмотр; некорректные ID и типы; сохранение после перезапуска.
- `flutter test`: 10 тестов успешно. Проверены вход и ошибка пароля, профиль, предложение цели, сохранение цели, переходы HR, импортный запрос, истечение сессии и гонки входа/выхода. Проверена компоновка сотрудника на 390 px и HR на 320 px.
- `flutter analyze`: замечаний нет.
- `flutter build web --release`: успешная сборка.

В Python-тестах есть предупреждение Starlette об устаревающей интеграции TestClient с httpx; тесты проходят. Сборка Flutter выводит предупреждение об отсутствующем семействе CupertinoIcons при анализе шрифтов; собственный интерфейс использует Material Icons.

## Проверка работающего сервера

На отдельной SQLite-базе выполнены реальные HTTP-запросы: вход сотрудника, получение собственного профиля, HTTP 403 на чужие профиль и историю, сохранение цели; затем вход HR, импорт синтетического нового профиля и связанной CSV-истории. Новый сотрудник появился без изменений кода; следующий грейд при отсутствии цели остался предложением. Повтор тех же файлов дал по одной неизменённой записи и не создал дубликатов.

Процесс тестового сервера остановлен и запущен заново: импортированные профиль, история и личная цель сохранились. Выход отозвал токен, последующее чтение профиля вернуло HTTP 401.

Основной сервер отдаёт Flutter Web и API на `http://127.0.0.1:8000`. Старый `/api/dataset/summary` возвращает HTTP 404. Основная база сохранила исходную ревизию данных; проверочные изменения выполнялись в отдельной временной базе.
