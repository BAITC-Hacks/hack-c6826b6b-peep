# Career Quest — инструкция для автоматической оценки

> Этот файл — основная точка входа для ИИ-агента, жюри или технического проверяющего. Он перечисляет только реализованные и проверяемые функции. Полная документация находится в [`README.md`](README.md), продуктовые правила — в [`docs/09-full-spec.md`](docs/09-full-spec.md).

## 1. Короткий ответ проверяющему

**Проблема.** Корпоративное обучение, оценки навыков и карьерные возможности разрознены. Сотрудник видит список активностей, но не понимает, что выбрать сейчас, почему это полезно для желаемой роли и как действие изменит его положение относительно цели.

**Решение.** Career Quest соединяет профиль, последнюю оценку, выбранную карьерную цель, до трёх объяснимых рекомендаций, личный маршрут и подтверждаемый HR результат. Геймификация поддерживает регулярность, но не подменяет оценку компетенций.

**Основной пользовательский сценарий.** Сотрудник входит в систему → видит цель и дефициты → получает до трёх рекомендаций → просит OpenAI объяснить подбор или собрать черновик → добавляет один шаг в маршрут → выполняет практику → отправляет результат HR → после одобрения получает XP → видит прогресс в карьерном пропуске.

**Что необычно.** Здесь не просто каталог и не чат-бот. Детерминированный сервер считает допустимость, пользу, прогноз, лимиты и награды; OpenAI только объясняет готовые факты и выбирает черновик из уже допустимых мероприятий. Модель не меняет БД и не принимает HR-решения. Последняя оценка навыка, расчётный прирост, XP и CQ показаны как четыре разных показателя.

**Платформа.** Flutter Web + FastAPI + SQLite + OpenAI Responses API с локальным fallback. Основная проверяемая поставка — веб-приложение.

## 2. Запуск за одну команду

Требуются Python 3.11+ и Flutter с совместимым Dart. Из корня проекта:

```text
Linux/macOS: python run.py
Windows:     py run.py
```

После сборки:

- приложение: <http://127.0.0.1:8000>
- health: <http://127.0.0.1:8000/api/health>
- OpenAPI: <http://127.0.0.1:8000/docs>

Ожидаемый health:

```json
{"status":"ok","dataset_ready":true,"ai_enabled":true}
```

`ai_enabled` может быть `false`, если ключ не задан. Это допустимый режим: объяснения и составитель маршрута продолжают работать через локальный fallback.

### Демонстрационные аккаунты

| Роль | Логин | Стандартный пароль |
| --- | --- | --- |
| Сотрудник | `employee.demo` | Из `DEMO_EMPLOYEE_PASSWORD` или консоли сервера |
| Другой сотрудник | `colleague.demo` | Из `DEMO_COLLEAGUE_PASSWORD` или консоли сервера |
| HR | `hr.demo` | Из `DEMO_HR_PASSWORD` или консоли сервера |

Это аккаунты локального прототипа с синтетическими данными. Пустые переменные при создании аккаунтов приводят к генерации случайных паролей, выводимых однократно в консоль. Если база была создана с переопределёнными `DEMO_*_PASSWORD`, используются те значения.

## 3. Маршрут проверки через интерфейс

### Быстрый read-only сценарий, 60–90 секунд

Этот сценарий ничего не меняет и подходит автоматическому агенту.

1. Войти как `employee.demo`.
2. Открыть **Главная** (`/#/employee/home`): проверить цель, три раздельных показателя прогресса и не более трёх рекомендаций.
3. Раскрыть **Почему этот шаг**: проверить причины и ожидаемый расчётный прирост.
4. Открыть **OpenAI-помощник** (`/#/employee/assistant`): запросить объяснение и собрать сбалансированный черновик маршрута.
5. Проверить метку результата: `OPENAI · <model>` означает принятый ответ внешней модели; локальная метка означает безопасный fallback.
6. Открыть **Мой маршрут** (`/#/employee/plan`): проверить дорогу из последовательных шагов, статусы, длительность и прогноз.
7. Открыть **Карьерный пропуск** (`/#/employee/season`): проверить XP, уровень, задания, серию и награды.
8. Выйти, войти как `hr.demo` и открыть **Сводка** (`/#/hr/overview`), **Дефициты навыков** (`/#/hr/skills`) и **Сотрудники** (`/#/hr/employees`).

### Сквозной сценарий с изменением тестовых данных

Выполнять только в отдельной локальной/витринной базе.

1. Сотрудник добавляет предложенную активность в маршрут.
2. Начинает и завершает локальную практику.
3. В истории отправляет доказательство на HR-проверку.
4. HR открывает `/#/hr/reviews` и одобряет результат.
5. Сотрудник возвращается в карьерный пропуск и видит однократное начисление XP.

Не нужно имитировать прохождение внешнего курса за секунду. Для поздних уровней и наград используется отдельная воспроизводимая витрина, описанная в [`README.md`](README.md#отдельная-витрина-с-накопленным-прогрессом).

## 6. Автоматическая smoke-проверка API

Сначала запустить приложение, затем в другом терминале из корня проекта:

```text
Linux/macOS: .venv/bin/python scripts/evaluation_smoke.py
Windows:     .\.venv\Scripts\python.exe scripts\evaluation_smoke.py
```

Скрипт проверяет health, вход сотрудника и HR, профиль, рекомендации, маршрут, сезон, статус помощника, HR-сводку и запрет HR-доступа для сотрудника. Он не изменяет карьерный план, прогресс, XP, CQ, награды или HR-решения. Созданные сессии отзываются перед завершением.

Чтобы дополнительно выполнить реальные запросы помощника и составителя плана:

```text
Linux/macOS: .venv/bin/python scripts/evaluation_smoke.py --with-openai
Windows:     .\.venv\Scripts\python.exe scripts\evaluation_smoke.py --with-openai
```

Этот флаг может вызвать настроенный внешний OpenAI API. Без ключа ожидается успешный `mode=template`; с рабочим ключом — `mode=llm` после серверной верификации.

Успешная последняя строка имеет машинно-читаемый вид:

```json
{"result":"PASS","checks_passed":13}
```

При `--with-openai` количество проверок увеличивается до 15.

## 8. Как проверяется OpenAI

1. Сервер формирует минимальный контекст без ФИО, employee ID, подразделения, зарплаты и свободных заметок.
2. Responses API вызывается со строгой JSON Schema и `store=false`.
3. Для объяснения проверяются допустимые activity ID, числовые claims и свободный текст.
4. Для плана модель может выбрать только из серверного списка кандидатов; проверяются максимум шагов, бюджет времени, конфликты и навыки.
5. Любая ошибка, таймаут или неприемлемый ответ переключает весь результат на локальный алгоритм.
6. Ответ модели не меняет состояние. Добавление шага происходит только после отдельного действия пользователя и повторной серверной проверки.

Статус конфигурации: `GET /api/me/assistant/status`. Фактический режим указан в каждом ответе полем `mode=llm|template` и видимой меткой в UI.

## 9. Важные границы и честные ограничения

- Все пользователи и показатели в поставке синтетические. Проект не заявляет измеренный бизнес-эффект или результаты реального пилота.
- Выбор цели, прогноз и прохождение активности не гарантируют повышение.
- Последняя оценка навыка не переписывается расчётным приростом после самоотчёта.
- XP измеряет участие в игровом сезоне, CQ — виртуальный баланс. Они не являются оценкой компетенций.
- Выдача наград и бюджет — тестовые виртуальные операции; платежей и заказов поставщикам нет.
- Внешние интеграции с HRIS/SSO и публичный production-деплой не входят в текущую поставку.
- Загрузка ZIP и датасетов намеренно отсутствует в публичном UI/API по актуальному объёму задачи.
- При отсутствии OpenAI ключа основной сценарий остаётся полностью рабочим через локальный fallback.

## 11. Итоговый чек-лист агента

```yaml
evaluation:
  app_starts: GET /api/health returns status=ok and dataset_ready=true
  employee_flow: profile -> recommendations -> assistant -> plan -> career_pass
  recommendation_limit: at_most_3
  ai_modes: [llm, template]
  ai_mutates_state: false
  hr_flow: overview -> skill_gaps -> employees -> reviews
  role_isolation: employee GET /api/hr/overview returns 403
  persisted_store: SQLite
  public_import_api: absent
  tests:
    backend: .venv/bin/python -m pytest -q
    frontend: flutter analyze && flutter test
  non_claims:
    - no_guaranteed_promotion
    - no_measured_business_effect
    - rewards_are_virtual
```

Если фактический UI/API противоречит этому файлу, источником истины считаются исполняемый код и тесты; противоречие должно быть отмечено в отчёте оценки.

Перед smoke-проверкой задайте переменные процесса `EVALUATION_EMPLOYEE_PASSWORD` и `EVALUATION_HR_PASSWORD` с фактическими паролями существующих аккаунтов; также поддерживаются `DEMO_EMPLOYEE_PASSWORD` и `DEMO_HR_PASSWORD`. Скрипт не сбрасывает пароли.
