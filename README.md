# Career Quest

Понятный путь от текущих навыков к карьерной цели: рекомендации объясняют пользу каждого шага, план фиксирует действия, а сезонные задания и награды поддерживают регулярность. **Последняя оценка навыков, расчётный прирост, XP и CQ-монеты — четыре отдельных показателя.**

Flutter Web · FastAPI · SQLite. Интерфейс на русском, исходные названия и описания материалов сохранены. Требования: [полная спецификация](docs/09-full-spec.md), [реализация и проверка](docs/10-implementation.md), [админка и карта настроек](docs/11-admin.md), [матрица проверок](docs/build_matrix.md). По указанию команды загрузка ZIP/датасетов исключена: в интерфейсе и HTTP API импорта нет. Админка реализована для Web.

## Запуск на Linux и Windows

Установите Python 3.11+ и Flutter, добавьте их в PATH. Из корня проекта:

```sh
python run.py
```

Команда создаёт `.venv`, устанавливает закреплённые зависимости, собирает Flutter Web и запускает [приложение](http://127.0.0.1:8000). Для Windows допустима команда `py run.py`. Повторный запуск без изменений фронтенда: `python run.py --skip-build`. Другой порт: `python run.py --port 8001`.

Скопируйте `.env.example` в `.env`, если нужны собственные настройки. Сервер читает `.env` автоматически. Существующая SQLite сохраняется между перезапусками; новые исходные файлы не затирают данные пользователей.

## Вход

Логины: `employee.demo`, `colleague.demo`, `hr.demo`, `admin.demo`, `superadmin.demo`. У сотрудника и коллеги разные личные профили. Кнопки на лендинге заполняют **только логин**. Администратор входит тем же способом по адресу [админки](http://127.0.0.1:8000/admin); HR открывает разрешённые разделы кнопкой управления в шапке.

При создании новых аккаунтов пароли берутся из `DEMO_EMPLOYEE_PASSWORD`, `DEMO_COLLEAGUE_PASSWORD`, `DEMO_HR_PASSWORD`, `DEMO_ADMIN_PASSWORD`, `DEMO_SUPERADMIN_PASSWORD`. Если переменные пусты, сервер создаёт случайные пароли и однократно печатает их в локальной консоли. При обновлении существующей базы добавляются только отсутствующие аккаунты. Существующие пароли сохраняются; редактирование `.env` не сбрасывает их. В репозитории и Flutter паролей нет; константы тестов предназначены только для временных тестовых баз.

Сессия по умолчанию живёт восемь часов, отзыв выполняется сервером. Токен хранится только в памяти клиента: обновление страницы требует входа. Административные права проверяются сервером; блокировка, смена доступа или сброс пароля отзывают сессии. Новый временный пароль необходимо сменить. По умолчанию HR читает сотрудников, проверяет результаты и обрабатывает выдачу; дополнительные права назначает super_admin.

## Что работает

- Личная цель и предложение следующего грейда, требования ролей, предпочтения времени и формата, разделение оценённых и расчётных навыков.
- Объяснимый подбор до трёх активностей; каталог с фильтрами; личный план, порядок, замена, старт, архивирование, завершение и история.
- Симулятор альтернативной цели и набора шагов с отдельным подтверждением сохранения; паспорт развития с выгрузкой Markdown; карьерный помощник.
- HR-сводка, дефициты, фильтры подразделения/роли/грейда/периода, профили сотрудников и CSV с защитой от формул.
- Сезоны на 90 дней, 100 уровней, два вычисляемых задания в день, три попытки, серии и две защиты пропуска, недельные миссии, достижения, лидерборд и зафиксированные итоги.
- Отправка результата практики на проверку HR; XP после одобрения; подарки пропуска, CQ-кошелёк, магазин из 32 SKU, заявки, резерв остатков, выдача, отмена и однократный возврат.
- HR-управление сезонами, составом черновика, магазином и подарочными пулами; бюджет с отдельными обязательствами, резервом заявок, расходами и освобождённым остатком.
- Админка: аккаунты и разрешения, сотрудники и оценки, подразделения, навыки, роли и грейды, активности и рекомендации, сезоны и редактор пропуска, задания, достижения, серии, рейтинги и номинации, награды, пулы, склад, выдача, кошельки и бюджет.
- Версии конфигурации, черновики, серверный предпросмотр, публикация и восстановление как новый черновик; коррекции XP/CQ/проверок/выдачи/итогов с отдельным журналом. Оформление, тексты кабинета и параметры помощника применяются через API без пересборки Flutter.

Числа выше описывают начальный шаблон. Лимит шагов, награды, пороги XP, длина пропуска и правила заданий читаются из опубликованной конфигурации. Денежные изменения требуют `economy.publish`; это право изначально есть у `superadmin.demo`, обычный `admin.demo` может готовить соответствующие черновики.

Все награды, выдача и бюджет в этом прототипе **виртуальные**. Реальной оплаты, бронирования, заказа у продавца или кадрового решения приложение не выполняет.

## Подключение OpenAI

В корневом `.env`:

```dotenv
AI_MODE=llm
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-4o-mini
```

Перезапустите сервер и откройте «Карьерный помощник». При успешном ответе интерфейс показывает режим AI. Ключ остаётся в Python-процессе; его нельзя передавать через Flutter `--dart-define`. Используется [OpenAI Responses API со Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), `store=false`, таймаут восемь секунд, без повторных платных запросов.

Передаются цель, обезличенные навыки и уже рассчитанные рекомендации. ФИО, подразделение, зарплата, заметки и данные других сотрудников в запрос не входят. ИИ объясняет рассчитанное сервером; не начисляет навыки/XP и не принимает решений. Ответ проверяется по допустимым ID и численным утверждениям. При отсутствии ключа, сетевой ошибке или неприемлемом ответе автоматически используется локальное объяснение с пометкой «Шаблон». Для работы без внешней сети оставьте `AI_MODE=template`.

## Две отдельные демонстрации

Обычная база `data/local/career.sqlite3`: исходные профили и история, первый сезон, нулевые игровые счета. При обновлении старой версии исходные таблицы сохраняются, новый доменный слой создаётся отдельно.

Для показа 100-го уровня, магазина и итогов сезона создайте **новый** файл:

```sh
python -m backend.showcase --db data/local/showcase.sqlite3
```

Команду выполняйте Python из `.venv` (`.venv/bin/python` на Linux, `.venv\Scripts\python.exe` на Windows). Она откажется перезаписывать существующую или основную базу. Витрина строится через тот же игровой движок: правильные ответы за 67 дней, реальные правила бонусов, отдельный прошлый сезон, две проверки и две заявки. Прямой установки баланса нет.

Для просмотра задайте `CAREER_DB=data/local/showcase.sqlite3` в `.env` и перезапустите сервер. В интерфейсе будет метка «Витринный сценарий». Уберите эту переменную для возврата к основной базе. Секреты, базы и сборки игнорируются Git.

## Разработка и проверки

Linux:

```sh

cd frontend
flutter analyze

flutter build web
```

В Windows замените путь к Python на `.venv\Scripts\python.exe`. Для разработки интерфейса: `flutter run -d chrome --web-port 8080`, сервер — `.venv/bin/python -m uvicorn backend.main:app --reload`. API: [Swagger](http://127.0.0.1:8000/docs).

Проверки используют временные синтетические SQLite и управляемые часы. Ключевые контрольные результаты: `73.6111 → 79.8611 → 85.4167%`; полный пропуск — `4800 CQ` и `720000 ₸` материальных лимитов; две daily за 90 дней — `27790 XP`, 100-й уровень на 67-й день.

## Хранение и ограничения прототипа

Исходный набор сохраняется отдельно от доменного состояния. Все изменения карьеры, игры и наград сериализованы транзакцией SQLite `BEGIN IMMEDIATE`; API проверяет `expected_revision` и UUID `Idempotency-Key`, а начисления дополнительно защищены бизнес-ключами. Фоновый таймер и запросы восстанавливают пропущенные переходы сезона. Часы клиента не участвуют в начислениях.

Доменное состояние этого локального прототипа хранится в одной версионированной JSON-записи SQLite. Это упрощает атомарность и сохранение старых данных; для большого многопользовательского внедрения нужны нормализованные таблицы, отдельные фоновые задачи и корпоративная авторизация.

Исходная шкала 0–5 явно преобразована в 0–100. В исходнике нет точного расписания с часами и материалов LMS, поэтому исходные мероприятия представлены как локальные самостоятельные практики с инструкциями. Это не запись на реальные банковские мероприятия; оригинальные поля сохранены. Подробности адаптации — в `docs/10-implementation.md`.
